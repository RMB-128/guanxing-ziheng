## 一、项目概述

观形智衡是一套融合计算机视觉（MMPose + SAM）、中医辨证与多智能体协同决策的居家式体态健康自评系统。项目从需求分析到临床验证（协和医院对照）完整走通，并获得省一等奖。

## 二、我的角色与贡献

在这一项目中，我的主要职责包括：

1. **视觉算法模块**：参与了MMPose人体关键点检测与SAM人体分割的集成实现，配置了Python环境（CUDA 11.8 + PyTorch 2.0.0），确保MMPose与SAM的版本兼容
2. **系统调试与测试**：参与了视觉算法管线的端到端测试，配合完成了关键点精度验证（横向误差<8‰肩宽、纵向误差<3‰身高）和SAM分割IoU验证（>0.98）
3. **技术文档撰写**：参与了技术文档中视觉算法设计（3.2节）和测试报告（4.2节）的内容编写
4. **系统部署支持**：协助完成了FastAPI后端的依赖环境配置与前后端数据交互调试

## 三、技术收获

### 3.1 计算机视觉工程化能力
- 掌握了MMPose工具箱的安装配置、模型选型（HRNet vs ResNet vs LiteHRNet）与推理链路
- 理解了SAM的分割原理——图像编码器（ViT-H）提取全局特征、提示编码器处理点/框/掩码输入、掩码解码器融合特征并输出多候选掩码
- 学会了在单目图像中处理视角偏差（PCA主轴估计 + 仿射变换校正）的几何校正思路

### 3.2 深度学习环境管理
- 深刻理解了CUDA版本、PyTorch版本、mmcv/mmdet/mmpose之间的版本依赖关系
- 积累了conda环境隔离、pip版本冲突排查的实际经验
- 学会了在GPU服务器和非GPU环境（测试服务器）之间做差异化部署

### 3.3 全栈开发认知
- 通过FastAPI + Vue 3的前后端分离架构，理解了RESTful API设计、前后端数据交互、以及SQLAlchemy ORM的数据库操作模式
- 见证了从需求分析→概要设计→详细设计→测试验证→部署上线的完整软件工程流程

### 3.4 临床验证意识
- 第一次接触"用三甲医院诊断作为算法输出对照"的验证方法论
- 学习了误差阈值比（ETR）的设计思想：不仅报告算法精度，还要评估算法误差对临床判定的干扰程度——这是一个从"工程思维"向"产品思维"跃迁的关键认知

## 四、不足与反思

### 4.1 我的技术深度不够
我在项目中承担的多为执行层面的工作（环境配置、代码调试、数据测试），对视觉算法的核心创新（如置信度筛选的Prompt策略、PCA校正的必要性证明、11项指标数学模型的推导）参与深度不足。如果重来一次，我会在以下方面提前准备：
- 提前自学MMPose的源码（至少理解HRNet的backbone设计和高分辨率特征保持机制）
- 在SAM模块中，独立跑一遍从"原始图像 → 手工标注关键点 → 构造Prompt → 评估IoU"的完整pipeline，而不是依赖团队成员已经搭好的代码框架
- 对每个体态指标，从医学文献中追溯其临床阈值来源，而不是仅仅接受"这个指标这样算是对的"

### 4.2 文档与项目管理意识需要加强
团队在开发过程中没有建立统一的实验记录规范，导致部分测试结果的可复现性需要事后回溯。如果重来，应该从第一天就建立：
- 代码版本管理（Git分支策略）
- 实验记录模板（模型配置/超参数/数据集/结果/关键发现）
- API接口文档（FastAPI的自动生成Swagger文档利用不足）

### 4.3 时间分配可以更优化
视觉算法模块的调试占用了大量时间（尤其是MMPose和SAM的环境兼容问题），导致对中医模块和多智能体架构的理解停留在表面。更好的做法是在项目初期就做一次完整的依赖环境调研，把环境冲突提前解决，而不是在开发中不断救火。
